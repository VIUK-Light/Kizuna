# 国際化（i18n）の方針

Kizuna のUI文言は現在 **2つの仕組み** が共存しています。この文書は、どちらを
いつ使うか、最終的にどこへ向かうかを明確にするものです（Issue #287）。

## 現状

| 仕組み | 対象 | 状態 |
| --- | --- | --- |
| `KizunaCopy.text(japanese:english:)` | 既存画面の大半 | レガシー（段階的に置換） |
| `Localizable.xcstrings`（String Catalog） | 一部の `LocalizedStringKey` | 追加先 |

`KizunaAIApp` の `.environment(\.locale, ...)` は `LocalizedStringKey`
（`Text("key")` 形式）にのみ効果があり、`KizunaCopy` が返す `String` には
効きません。両者が混在する画面では、実際の表示言語は `KizunaCopy.language`
（UserDefaults の `kizuna.language`）で決まります。

## 方針

1. **新規画面・新規文言では `KizunaCopy.text` を使わない。**
   String Catalog（`Localizable.xcstrings`）へキーを追加し、`Text("key")`
   （`LocalizedStringKey`）または `String(localized:)` で表示する。
   Xcode の翻訳エディタで未翻訳・抜けを検出できる状態を維持する。

2. **既存の `KizunaCopy.text` 呼び出しは、画面単位で段階的に置き換える。**
   機械一括変換はしない。リファクタリングや機能変更で該当画面を触るタイミングで
   同時に移行する。移行した画面はこのファイル末尾のリストに記録する。

3. **複数形・数値・日付はロケールに追従させる。**
   - 複数形: 英語で単複が分かれる文言は `KizunaCopy.pluralText` を使う
     （String Catalog 移行後は `stringsdict` 相当の複数形エントリを使う）。
   - 日付・時刻: `DateFormatter` の固定書式（`HH:mm` 等）を新規コードで
     使わない。`Date.formatted(.dateTime.hour().minute())` 等の
     `FormatStyle` を使う（#289 で既存箇所も移行済み）。

4. **`KizunaCopy.text` は将来 deprecate する。**
   移行が一巡した時点で `@available(*, deprecated)` を付け、残存呼び出しを
   ゼロにしてから削除する。

## アプリ内言語切り替えについて

設定画面の「表示言語」は UserDefaults の `kizuna.language` を参照する。
String Catalog 側の表示もこの値に追従させる必要があるため、新規画面では
`KizunaCopy.text` と `LocalizedStringKey` が混在しないよう、画面単位で
統一すること。
